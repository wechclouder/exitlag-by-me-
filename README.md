# wetwiLAG

Минималистичное WPF-приложение для диагностики сети и аккуратного управления некоторыми настройками Windows. Приложение предназначено для Windows 10/11 x64 и написано на C#/.NET 10.

> **Статус: ранняя, проверенная Release-сборка; это не законченный игровой ускоритель.** Приложение выполняет реальные измерения и показывает недоступные данные как «Недоступно». Оно не обещает уменьшить пинг, не меняет провайдера маршрутизации и не заявляет о подключении к серверам Fortnite без доступной информации об их адресах.

## Что уже реализовано

- **Сетевые измерения:** асинхронный ICMP ping, среднее время ответа, джиттер на основе последовательных успешных ответов и потеря пакетов на основе фактических ответов. Есть проверка DNS, ограниченная трассировка маршрута и измерение скорости передачи по счётчикам выбранного сетевого адаптера. Первый интервал измерения скорости явно недоступен, пока не накоплены два замера.
- **Адаптеры:** обнаружение интерфейсов Windows, состояние, IP-адрес, шлюз, DNS, MTU и скорость канала.
- **Fortnite:** определение наличия запущенного процесса игры. Windows не предоставляет этому приложению проверенный адрес игрового сервера; статус процесса не выдаётся за статус подключения к матчу.
- **Безопасный оптимизатор:** режимы `SAFE`, `MANUAL` и `RESTORE`; чтение настроек DNS и схемы электропитания; индивидуальное подтверждение изменений, неизменяемые timestamped JSON-backup-файлы, проверка результата и предпринятый откат при ошибке. Доступны настройка DNS, переключение на встроенную High performance-схему и отключение поддерживаемого адаптером selective suspend.
- **Откат:** отдельная кнопка восстановления для каждой категории, подтверждение перед восстановлением, снимок состояния до отката, проверка восстановленного значения. Резервная копия исходного значения не перезаписывается.
- **Профили:** создание, редактирование, удаление и выбор профиля с целью измерения и предпочтительным сетевым адаптером. Выбор профиля не изменяет настройки Windows.
- **История:** сохранение реальных результатов измерений, график из успешно измеренных значений и очистка истории с подтверждением.
- **Интерфейс:** навигация, светлая/тёмная тема, акцентный цвет, масштабирование, видимость и положение боковой панели, перетаскивание и изменение ширины виджетов, скрытие/восстановление карточек, сброс раскладки, создание/изменение/переименование/удаление/выбор именованных пресетов.
- **Хранение:** настройки и история сохраняются атомарной записью; пользовательские данные приложения хранятся в `%LOCALAPPDATA%\\wetwiLAG`.
- **Публикация:** самодостаточная Release-сборка для `win-x64`; для запуска опубликованного `.exe` установка .NET не нужна.

## Честные ограничения

- Результаты ICMP зависят от блокировки ping, удалённого узла, провайдера и текущего маршрута. Нулевые, неуспешные и недоступные измерения не заменяются случайными цифрами. Латентность компьютера до произвольной тестовой цели не равна задержке до игрового сервера.
- Для трассировки используются стандартные ICMP-запросы; промежуточный маршрутизатор вправе не отвечать. `*` — тайм-аут, а не измеренный адрес.
- Схема High performance показывается доступной только если встроенная схема действительно обнаружена. Поддержка selective suspend зависит от адаптера и драйвера.
- Применение оптимизатора не тестировалось с изменением реальных системных настроек: сетевой адаптер, схема электропитания и DNS не изменяются автоматически при сборке или smoke-тестировании. Для MANUAL/RESTORE Windows может потребоваться явно запустить приложение от имени администратора; автоматической смены прав нет.
- Блокировка внешних узлов, ограничения ICMP и права администратора зависят от конкретного компьютера. Проводить изменения DNS и питания следует только после ознакомления с предупреждениями приложения.
- Перед широким использованием стоит дополнительно проверить интерфейс и разные типы адаптеров на других поддерживаемых компьютерах с Windows 10/11, включая сценарии отключения сети, повышенных прав и восстановления резервных копий.

## Сборка и тестирование

Установите **.NET 10 SDK** на Windows:

```powershell
dotnet build .\wetwiLAG.csproj --configuration Release
dotnet run --project .\Tests\wetwiLAG.SmokeTests.csproj --configuration Release
```

Инструкции для новых разработчиков и правила Pull Request находятся в [CONTRIBUTING.md](./CONTRIBUTING.md). Для CI используется solution `wetwiLAG.sln`; GitHub Actions проверяет Release-сборку и smoke-тесты и сохраняет автономный Windows x64 `.exe` как артефакт workflow.

Функциональные smoke-тесты запускают проверки допустимости целей, валидации DNS, записи и повторного чтения настроек, профилей и истории, неизменяемости backup-файлов, перечисления адаптеров, чтения текущих параметров, разрешения `localhost`, ограниченного loopback traceroute, реальных loopback ping-ответов и недоступного диагностического адреса. **Они намеренно не изменяют настройки Windows и не заменяют полноценную ручную проверку оптимизатора.**

Опубликовать автономный Windows x64 `.exe`:

```powershell
dotnet publish .\wetwiLAG.csproj --configuration Release --runtime win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -p:DebugType=none -p:DebugSymbols=false -o .\publish\win-x64
```

## Данные и конфигурация

Папка `%LOCALAPPDATA%\\wetwiLAG` содержит:

- `settings.json` — внешний вид, предпочтительный адаптер, порядок/видимость/размер виджетов и пресеты раскладки;
- `profiles.json` — профили приложения;
- `history.json` — сохранённые измерения;
- `optimizer-operations.json` — история изменений и восстановления;
- `backups\\` — отдельные, не перезаписываемые файлы резервных копий перед системными изменениями и восстановлением;
- `application.log` — диагностические сообщения приложения.

## Правила безопасности

Оптимизатор не отключает защиту Windows, Defender, firewall, обновления, IPv6, сетевые адаптеры и MTU; не меняет реестр, файлы и память игры; не модифицирует игровые пакеты, маршрутизатор или другие устройства сети. «SAFE» только читает и измеряет. Изменения в других режимах подтверждаются отдельно и сохраняются в резервной копии до применения.
